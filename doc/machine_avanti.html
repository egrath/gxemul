GXemul: AlphaStation 200/400 ("Avanti") emulation

Back to the index.

The AlphaStation 200 and 400 (code-named "Avanti") were Digital's first PCI-based Alpha workstations, introduced in 1994. They are built around the DECchip 21071 (APECS) core logic chipset, with PCI and ISA buses, and were supported by both of Digital's consoles: SRM (for Digital UNIX / Tru64 and OpenVMS) and ARC (for Windows NT).

GXemul emulates:

  • Models (the "model" in the configuration):
    • 200: AlphaStation 200 4/166, DECchip 21064 (EV4) at 166 MHz.
    • 200-233: AlphaStation 200 4/233, 21064A (EV45).
    • 400: AlphaStation 400 4/233, 21064A, three PCI slots, no on-board Ethernet.
    • 250: AlphaStation 250 4/266, 21064A.
  • Execution of the genuine DROM (diagnostic ROM, with its power-up tests) and the SRM V7.0 or ARC 4.58 console from the flash.
  • DECchip 21071 (APECS): the COMANCHE memory controller and the EPIC PCI bridge, with direct mapped and scatter/gather DMA windows.
  • Intel 82378 (SIO) PCI-to-ISA bridge, with the 8259 interrupt controllers, the 8254 timer, DMA, the MC146818 real-time clock with 128 bytes of CMOS, the 8242 keyboard and mouse controller, two serial ports, the parallel port and the floppy controller.
  • NCR/Symbios 53C810 PCI SCSI controller, with its SCRIPTS processor; disk and CD-ROM images as SCSI targets.
  • DECchip 21040 on-board Ethernet (on the 200), or a DE500-BA (21143) in the first slot (on the 400).
  • ZLXp-E1 graphics (DECchip 21030 "TGA", 8 planes, Bt485), with the display enabled.

The following guest operating systems have been verified to install and run:

  • Tru64 UNIX V5.1A and V5.1B (multi-user, networking, CDE)
  • Windows NT Server 4.0, with Service Pack 6a (networking, Internet Explorer)


Firmware:

The machine runs the real firmware (the DROM, and the flash with the SRM and ARC consoles), from a single file: the dumps of the board's five ROM chips, concatenated in this order: 

	cat E13 E19 E33 E46 E47 > avanti.rom

The flash holds both consoles. Which one starts is a CMOS setting, as on the real machine: from SRM, set os_type NT and a power cycle (a restart of GXemul) start ARC; from ARC's Setup menu, "Switch to OpenVMS or Digital UNIX console", "Switch to Digital UNIX" and a power cycle start SRM again. The CMOS and SRM's environment are kept in the "nvram" file, and ARC's environment in the same file name with .wart appended.

SRM uses the serial console (COM1, tty0); ARC and Windows NT use the graphics card.

Using the Alpha Systems Firmware Update CD: the firmware CDs (e.g. versions 5.4 to 6.1) have the consoles for these machines in \ALPHA200 (AlphaStation 200 and 250, e.g. AS200_V7_0.EXE) and \ALPHA400 (AlphaStation 400, e.g. AS400_V72_1.EXE). These files are not ROM images: they are Digital's update program (APU) with the SRM and ARC images packed inside, and the DROM (E47) is not on the CD at all. So a ROM image as above is still needed to start the machine, but its flash part can be anything SRM starts from (an older version, or the same one). The update is then done as on the real machine, and the emulated flash keeps it.

These consoles have been flashed this way and boot, with the DROM 1.7 from the chip dumps, to SRM and from there Tru64 UNIX V5.1A:

The steps:

  1. Configure an "nvram" file (the new flash contents are saved in the same file name with .flash appended; once that file exists, it is used instead of the flash part of the ROM image), and put the firmware CD in the CD-ROM drive (ID 4).

  2. At SRM's prompt, boot the CD: 
    	>>> boot dka400
    The CD's loader names the platform and asks whether it is another one with the same system type; for an AlphaStation 400 it asks Is this really an "AlphaServer 400"?: answer n. It shows the README (Ctrl-C skips it) and the default bootfile for the machine (the newest one); press Return to use it, or type another one from the table, e.g. [ALPHA400]AS400_V71_2.EXE.

  3. The update program starts (AlphaStation 400 4/233 -- Firmware Update) with its Apu-> prompt. Program the flash: 
    	Apu-> update
	APU-I ARE YOU READY TO PROGRAM (SRM  ) ROM DEVICE ? (Y/N) y
	APU-I PRECHARGING (SRM  ) ROM DEVICE
	APU-I ERASING (SRM  ) ROM DEVICE
	APU-I PROGRAMMING (SRM  ) ROM DEVICE
	...
	APU-I PROGRAMMING (ARC  /AlphaBIOS) ROM COMPLETED
    It programs both consoles, SRM and ARC.

  4. Quit GXemul and start it again (the power cycle): the DROM starts the new console from <nvram file>.flash. To go back to the flash in the ROM image, delete that file.


Configuration:

The avanti presets (AlphaStation 200 and 400) are a good start. A configuration for an AlphaStation 200 with 128 MB, the graphics card, a 4 GB disk (an RZ29B), a CD-ROM and the on-board Ethernet on GXemul's simulated network: 

{
 "gxemul": 1,
 "name": "AlphaStation 200",
 "machine": {
  "type": "avanti",
  "model": "200",
  "memory_mb": 128
 },
 "boot": {
  "prom_emulation": false,
  "rom": "avanti.rom",
  "nvram": "nvram.bin"
 },
 "drives": [
  {
   "file": "rz29.img",
   "kind": "disk",
   "id": 0,
   "vendor": "DEC",
   "product": "RZ29B    (C) DEC",
   "revision": "0016"
  },
  {
   "file": "cdrom.iso",
   "kind": "cdrom",
   "id": 4,
   "readonly": true,
   "vendor": "DEC",
   "product": "RRD45   (C) DEC",
   "revision": "0436"
  }
 ],
 "display": {
  "enabled": true
 },
 "network": {
  "enabled": true,
  "type": "simulated",
  "ipv4": "10.0.0.0",
  "ipv4len": 8,
  "gateway": true
 }
}

An empty RZ29B disk image has 8380080 sectors: 

	dd if=/dev/zero of=rz29.img bs=512 count=0 seek=8380080

On the simulated network, the gateway (and name server) is 10.0.0.254. If the host itself is inside 10.0.0.0/8, add a host route to it through the gateway in the guest.


Tru64 UNIX V5.1A and V5.1B:

Start the machine with the OS CD as the CD-ROM and an empty disk image. At SRM's >>> prompt on the serial console: 

	>>> boot dka400

Choose U.S. English, install all software, the mandatory kernel options, and the default AdvFS layout. Loading the subsets takes 35 (V5.1B) to 50 (V5.1A) minutes. The installer reboots through SRM by itself, configures the subsets, builds a kernel for the machine (cpu "DEC2100_A50"), reboots again, and comes up to login:. (V5.1B may need boot dka0 -flags A at the SRM prompt after its first reboot; V5.1A does it all by itself.)

The on-board 21040 is tu0 (a DE500-BA on the 400 is too); with the display on, the graphics card is tga0. If the kernel was built before the display or the network were enabled, rebuild it with doconfig, and set up the network with netsetup or rcmgr.


Windows NT 4.0:

Windows NT 4.0 for Alpha supports the AlphaStation 200/400 (its HAL is HALAVANT.DLL). The NT Server 4.0 CD (the multi-architecture one, with an \ALPHA directory) installs from the ARC console:

  1. Use a configuration as above, with the NT CD in the CD-ROM drive, the display and the network enabled, and an empty disk image.

  2. In SRM, switch to ARC (see Firmware): 
    	>>> set os_type NT
    and restart GXemul. ARC starts on the graphics card. On the first start it asks for the language, and wants "Set default environment variables" and "Set default configuration" in its Setup menu (then "Supplementary menu, and save changes").

  3. Make the system partition, a small FAT partition from which ARC starts NT: in the Supplementary menu, "Run a program": 
    	scsi(0)cdrom(4)fdisk(0)\alpha\arcinst
    "Configure partitions", "Create system partition", on the disk, 10 MB.

  4. In the Supplementary menu, "Install Windows NT from CD-ROM". Text-mode setup finds the "Digital AlphaStation 200/400 Family", the "Symbios Logic C810" SCSI controller and the "Digital ZLXp-E" graphics. Create an NTFS partition for NT in the rest of the disk (e.g. 2000 MB), and let setup copy the files; it restarts through ARC by itself.

  5. The graphical setup asks for the CD key (the CD's kind, retail or OEM, decides which kind it takes), the licensing mode, the computer name, the server type (a stand-alone server is simplest) and the Administrator password. For the network, "Start Search" finds the "DEC PCI Ethernet DECchip 21040"; keep its "AutoDetect" connection type. GXemul's simulated network has no DHCP server, so give TCP/IP a fixed address, e.g. 10.0.0.2, mask 255.0.0.0, gateway 10.0.0.254.

  6. After the last restart, ARC boots "Windows NT Server Version 4.00", and NT comes up to the logon screen (Ctrl-Alt-Del).

Service Pack 6a: with the Service Pack 6a CD in the CD-ROM drive, run \alpha\update\update.exe from it in NT (e.g. e: is the CD-ROM), accept the license, and restart when it asks. NT then reports "Version 4.0 (Build 1381: Service Pack 6)", "Revised Service Pack 6a".


Limitations:

  • The TGA's DMA and 3D modes are not emulated (none of the guests above use them).
  • SRM's graphics console needs the card's x86 option ROM, which is not there: SRM stays on the serial console.
  • The SCSI targets don't disconnect, and only LUN 0 exists.
  • No caches are modelled.

The development notes, with the details of the hardware and of what the firmware and the guests expect, are in doc/avanti-plan.md.
